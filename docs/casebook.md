# 문체 교정 사례집

기존 대화에서 실제로 문제가 제기된 표현과 그 반례를 함께 기록한다.

**원칙:** 아래의 '교정 예시'는 특정 문맥에서 가능한 편집안이다. 원문을 일괄 치환하는 사전이 아니다. 문체 이외의 사실관계, 수치, 논리, 정보의 충분성은 평가하지 않는다.

## A. 실제로 삭제하는 것이 적절한 문장

### 불필요한 진행 안내

원문:

> 한 가지 짚고 넘어가겠습니다. 개인정보는 외부 서버에 전송되지 않습니다.

잘못된 교정:

> 먼저 말씀드리겠습니다. 개인정보는 외부 서버에 전송되지 않습니다.

교정 예시:

> 개인정보는 외부 서버에 전송되지 않습니다.

**이유:** 앞의 문장은 본문을 예고할 뿐이므로 다른 예고 문장으로 바꿀 필요가 없다. 단, 앞부분이 문서 구조상 실제 안내 기능을 갖는다면 삭제하지 않을 수도 있다.

### 독자의 반응을 예고하는 문장

원문:

> 한 가지 예를 보면 쓸모가 보입니다. 작업 4개의 '보통' 소요일을 더하면 14일입니다.

교정 예시:

> 작업 4개의 '보통' 소요일을 더하면 14일입니다.

**이유:** 예시 자체로 시작할 수 있는 문맥이라면 '쓸모가 보인다'는 예고를 생략한다.

## B. 한국어 어휘 결합이 어색한 문장

| 원문 | 특정 문맥에서 가능한 교정 | 검토 근거 |
| --- | --- | --- |
| 숫자를 움직여 봅니다 | 입력값을 변경합니다 | 수치 조정 작업을 불필요하게 물리적 동작으로 묘사 |
| 결과가 어떻게 흩어지는지 봅니다 | 결과의 분포를 확인합니다 | 통계 분야의 관용적인 어휘 결합 |
| 여기서 숫자와 말을 나눕니다 | 계산과 결과 해석을 분리합니다 | 기술적 절차에 부자연스러운 구어적 비유 |
| 계획에 유지합니다 | 계획에 포함합니다 / 계획을 유지합니다 | 조사와 목적어·동사의 결합 재검토 |
| 파일 대신 주소를 건넵니다 | 파일 대신 URL을 전달합니다 | 기술 문서에서 어색한 일상적 의인화 |
| 지금 기댈 수 있는 기준 | 현재 적용되는 기준 | 공식적인 업무·법률 설명에서 비유의 필요성 검토 |

교정 예시를 채택하기 전에 **실제 작업과 원문의 의도**가 일치하는지 확인한다. 특히 '계획을 유지한다'와 '계획에 포함한다'는 상황에 따라 의미가 다르다.

## C. 동사를 기계적으로 바꾸면 잘못되는 사례

| 기존 일괄 치환 발상 | 왜 문제가 되는가 |
| --- | --- |
| '옮겨갑니다' → '됩니다' | 이동·진행·변화의 의미가 사라질 수 있다. |
| '가릅니다' → '달라집니다' | 판별·결정에 관한 의미가 단순한 차이로 변할 수 있다. |
| '남습니다' → '결론은 ~입니다' | 실제로 남아 있는 상태나 지속성을 삭제할 수 있다. |
| '조입니다' → '고정합니다' | 제한을 강화한다는 뜻과 값을 고정한다는 뜻은 다르다. |
| '붙습니다' → '맞습니다' | 연결·부착·합류 등 문맥별 의미가 다르다. |
| '박습니다' → '고정합니다' | 물리적 동작, 확정, 강한 강조 등의 뉘앙스가 손실될 수 있다. |

원문:

> 이것이 성패를 가릅니다.

이는 자연스러운 한국어 문장이다. '가르다'가 AI 문체 관찰 사례에 포함되어 있다는 이유로 교정하지 않는다.

반면 한 글 안에서 전혀 다른 주제마다 '생산성을 가릅니다', '작업 시간을 가릅니다', '향방을 가릅니다' 같은 문장이 반복된다면 **동사 선택의 편중**을 검토할 수 있다. 이 역시 실제 문맥을 보기 전에는 오류로 단정하지 않는다.

## D. '갈래'의 문맥별 차이

1. '문학은 크게 네 갈래로 구분합니다.' — 분야에서 통용되는 분류어다.
2. '해결 방법은 세 갈래로 나뉩니다.' — 문맥에 따라 충분히 자연스럽다. 수정이 필수는 아니다.
3. '앞으로 우리가 선택해야 할 갈래는 두 가지입니다.' — '갈래를 선택하다'라는 결합의 적절성을 문서 유형에 맞춰 확인한다.

세 문장 모두 같은 단어를 사용하지만 같은 평가를 내릴 수 없다.

## E. 제목과 완곡한 표현

| 원문 | 교정 가능한 상황 | 그대로 두는 상황 |
| --- | --- | --- |
| 이렇게 보이면 성공 | 업무 매뉴얼의 '실행 결과 확인' | 친근한 실습 콘텐츠에서 의도한 어조일 때 |
| 숫자를 움직여 보기 | 수치 계산 매뉴얼의 '입력값 변경과 결과 비교' | 비유를 의도한 비전문가 대상의 가벼운 제목일 때 |
| 7일을 전부 채우지 않는 편이 현실적입니다 | 중립적인 절차 지침에서 간명하게 정리 | 조심스러운 조언이라는 태도를 유지해야 할 때 |
| 짧게 짚습니다 | 설명 예고에 불과하다면 삭제 | 실제로 단락 간 연결이 필요한 글일 때 |

## F. 교정본도 다시 평가한다

최초 문장에서 AI식 표현을 제거하더라도 다음과 같은 문제가 새로 생길 수 있다.

- 동사를 '확인합니다', '검토합니다', '분석합니다'로만 통일
- 문장형 제목을 모두 기계적으로 명사형으로 바꿈
- 불필요한 안내를 삭제하는 대신 '핵심은'이라는 상투어를 삽입
- 지나치게 쉬운 표현을 모두 불필요하게 딱딱한 한자어로 바꿈
- 권고·가능성 표현을 삭제해 원문보다 단정적인 문장으로 만듦

**교정의 기준은 금칙어 제거가 아니라 결과 문장이 자연스러운지 여부다.**

## G. 사례를 계속 추가할 때

새 사례를 수집할 때는 **원문 / 앞뒤 문장 / 장르 / 언어적 문제 / 교정안 / 그대로 두어야 하는 반례**를 함께 기록한다. 예시를 고정된 판단 규칙으로 사용하지 않는다.
